# 开发说明

## 结构

```text
src/
  pet_base.py        Tk 窗口、刷新调度、跟随与菜单入口
  accessories.py     七种配件绘制、可见边界与侧边定位
  accessory_layout.py 双侧额度分配、关闭侧过滤与边缘回退
  appearance.py      主题、额度选择和时间文案
  base_menu.py       可拖动设置菜单
  pet_tracking.py    Windows 窗口识别与用户拖动跟随
  dpi_policy.py      唯一 DPI 边界：原生界面、逻辑位置适配
  smooth_surface.py  Pillow 超采样与 Windows 分层透明窗口
  usage_core.py      app-server 只读调用、数据规范化
tests/               无真实账号的单元测试
examples/            默认配置示例
scripts/             可分享源码打包
```

当前模块使用直接导入，入口为 `src/pet_base.py`，无需安装成 Python 包。

## 独立测试数据目录

可设置 `CODEX_PET_DATA_DIR` 指向测试目录，避免与日常配置共用：

```powershell
$env:CODEX_PET_DATA_DIR = Join-Path $env:TEMP 'codex-pet-accessories-demo'
.\.venv\Scripts\python.exe .\src\pet_base.py --smoke
Remove-Item Env:CODEX_PET_DATA_DIR
```

该环境变量仅控制配件自己的数据，不改变 Codex 登录目录。界面演示与冒烟检查不持久化演示设置。

## 新增样式

在 `accessories.py` 的 `STYLES` 注册样式，在 `render_accessories` 添加绘制分支；菜单会自动列出样式。保持百分比、未知数据、过期数据和倒计时的一致语义。左右两侧、浅深配色、0% / 100% / 未知额度及非整数缩放都需要验证。

## 当前紧凑尺寸

每格设计尺寸为 112×160，匹配当前 112 宠物尺寸。渲染测试应使用 HEIGHT 常量，禁止再假定 174。图案区与下方文字区分别排版，正常倒计时为单行；所有七样式在 150%/200% 绘制时检查文字边界和互不重叠。图形缩放发生在超采样坐标中，不再缩放已经完成的整个配件。

## 统一外观约定

`quota_colors=paired/theme` 控制周期双色或沿用主题强调色。双色身份依据有效周期时长：不足一天为短周期（常见 5 小时），一天及以上为长周期（常见一周）；未知周期保留中性色。身份不依赖窗口所在侧、列表索引或 primary/secondary 槽位，因此单周期、关闭侧和边缘合并不会改变身份。

`quota_palette` 只派生绘制颜色，不修改账户数据或设置。`progress_points` 按路径长度截取进度；轻羽羽轴和翅膀翼根都显示剩余额度，未知与 0% 不画活动进度。羽片 alpha 轮廓不随余量变化。

书签只旋转图案，文字单独水平绘制；默认下端朝外，镜像后朝内。电池、表盘和水晶保持同向。低额度提示点独立于周期强调色，不能覆盖文字。新增回归见 `tests/test_unified_design.py`。

## 定位与性能

配件进程与整个 Tk 界面线程统一使用 Per-Monitor V2；`initialize_native_dpi` 必须在创建 Tk 窗口前调用。配件、设置菜单、提示文字均直接按原生像素绘制。`target_size` 仅计算设计尺寸 × 当前窗口 DPI；不得从上一帧尺寸反推倍率。

唯一的坐标边界在 `dpi_policy.py`。宠物保存位置和布局计划继续使用逻辑坐标；Win32 位置读取、指针读取及只移动不改大小的 `position_logical_window` 在短暂逻辑上下文中转换。窗口尺寸完全由原生像素布局控制。`monitor_work_area` 和只读宠物跟踪允许逻辑上下文，内部不能运行 Tk。

禁止把整个 tick、follow、render、菜单操作或 Tk 事件循环包进逻辑 DPI 模式。禁止在逻辑上下文内调用 update、update_idletasks、geometry 或其他界面操作，这会让待处理的其他窗口布局也被重复缩放。不得恢复逐个 HWND 事后修尺寸的补丁。`tests/test_dpi_policy.py` 保护这条边界。

菜单所有字体、间距和几何从不可变的原始尺寸计算，每次使用窗口 DPI；不依赖全局 Tk 字号倍率，也不累乘上一次结果。位置不能直接保存 root.winfo_x/y，应使用 logical_window_position。跨 DPI 重排保留滚动和未保存输入。

固定验证入口：`python scripts/verify_windows.py`。它运行单元测试、菜单字体/实际子 HWND 像素/滚动/拖动验证、七样式在菜单打开时持续移动刷新验证、层级验证。`package_release.py` 强制先执行此入口，失败不生成新发布包；CI 的打包步骤也执行同一套检查。测试只用临时演示窗口，不操作原生宠物、账号、实际显示器缩放或个人设置。

2026-10-05：54项单元测试、11组菜单检查、88组完整界面场景及16组层级验证通过。统一前后146个配件位图与逻辑位置完全一致。真实屏幕实测为144 DPI（150%）；100%/125%/150%/200%的菜单计算往返经过模拟验证，混合DPI多显示器切换仍需真实设备覆盖，不能用模拟倍率冒充跨屏实测。

`ink_insets` 从绘制结果计算透明留白，`side_position` 将实际可见内容放到原生控件横向边界之外。透明边距不应拦截点击。

双侧使用两个独立窗口。先按周期排序和左右互换分配，再按用户显示侧筛选，防止关闭一侧后另一个周期意外补位。两个窗口共用一个 App、查询线程与倒计时缓存，隐藏一侧不会重新查询。

位置跟随默认每 80ms 检查，拖动期间每 25ms 检查；状态文件读取有独立限频。绘制与边界测量缓存按内容、样式和分钟更新，不随每次位置检查重新绘制。查询由后台线程运行，每次创建短期 app-server 进程并在完成或取消后关闭。

## 已知边界

- Windows 原生接口和窗口样式依赖当前桌面应用行为，尚无跨平台实现。
- 现有中文字体优先使用微软雅黑，其次黑体或 Segoe UI；未安装中文字体时可能缺字。
- 不读取原生按钮显隐状态，而是始终预留其空间。
- 额度接口与本地宠物状态格式变化后，可能需要更新定位或解析逻辑。


## 透明窗口生命周期回归

`verify_alpha_recovery.py` 必须覆盖首次绘制前隐藏后重新显示，单纯反复隐藏已有画面的窗口无法复现此故障。遇到ULW错误87只重置自己的透明图层并重试一次，其他错误继续上报；帧缓存只在真正提交成功后更新。该检查已并入固定验证入口和打包清单。


`verify_lifecycle_windows.py` 已并入固定验证入口，覆盖真实App退出分支和查询父子进程清理。2026-10-18另用独立任务进行195秒完整流程验证：真实计划任务自然触发，宿主/宠物状态及额度数据模拟；24轮隐藏/显示/透明恢复、退出和重启均通过。此测试未控制原生宠物开关。完整记录位于项目work/lifecycle-soak-2026-10-18。
